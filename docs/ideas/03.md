# Идея 3 — Диагностическая z: гидростатическая реконструкция вместо свободной головы

Ось рамки: **A** (что прогностично) + принцип 5 («жёстко — только точные тождества»).
Статус: предложена по итогам аудита; требует офлайн-потолка до GPU.

## Механизм

`y_nn` прогнозирует свободно {surface, T, r, u, v} и **один** канал z₁₀₀₀;
остальные 12 z-уровней не прогнозируются, а восстанавливаются интегрированием
гидростатики:

```
z_l = z_1000 + Σ R_d · T_v · Δln p        (матрица M_lnp — новый буфер)
```

T_v — из прогнозных T, r. Лосс не меняется: ошибка z теперь течёт градиентом в
T/q/z₁₀₀₀, т.е. z-супервизия превращается в дополнительный
физически-структурированный сигнал для температуры.

## Теоретическое обоснование

В p-координатах гидростатика — не приближение, а определение геопотенциала
данных: ERA5 сам строит z из T_v интегрированием. Это единственный класс
связей, который механизм-рамка (ось B, принцип 5) разрешает навязывать жёстко.
Прецедент — NeuralGCM: Φ диагностична, прогностические только u,v,T,q; все
спектральные ядра (IFS) устроены так же. Убирается самая хрупкая степень
свободы (z-невязка 137–199 — худшая по корпусу).

## Опора на факты проекта

- exp 10 §C: |z_t_hyd|/|z_t_obs| = 0.98; план §1.8 фиксирует «прогнозировать z
  как независимую не нужно», но в живой матрице (E9′/E-ω/E2/E1/E3′)
  эксперимента на это **нет** — ниша свободна.
- Осторожность: там же sign-corr тенденций −0.35 ⇒ обязательный **офлайн-потолок
  до GPU**: восстановить z из ERA5 T,r,z₁₀₀₀ на кропе и померить RMSE против
  истинной z (CPU-скрипт, ~час).

**Не входит в §2** (E8 — про сохранение ∑X оператором, другое).

## Скетч реализации

- Флаг `hydrostatic_z: bool` в `IAM4VP.__init__` (паттерн валидации соблюдён).
- Вмешательство после `readout` и после `_apply_physics_residual`
  (порядок: коррекция → реконструкция z).
- Денорм-буферы уже есть; маска уровней под рельефом по орографии (константы
  уже подгружаются для A2).
- ~100 строк + конфиг + tools-скрипт потолка. DDP нейтрально.

## Фальсифицируемое предсказание

- Офлайн-потолок: RMSE(z_hyd vs z_ERA5) достаточно мал на средних уровнях
  (сравнить с текущей z-RMSE модели на h1 — потолок должен быть ниже).
- В обучении: z500-RMSE h1–h6 не хуже −0/+1 % при идеальной межуровневой
  согласованности (толщины 1000–500 точны по построению); T850-RMSE −1 %
  (бонус от z-градиента).

Опровержение: z-RMSE +3 % и хуже ⇒ ассимиляционные инкременты ERA5 нарушают
тождество сильнее допустимого — количественный результат о пределах «точных
тождеств» в реанализе.

## Риски и стоимость

T_v требует q (конвертация r→q уже есть в кодовой базе); подземные уровни в
Скалистых горах — маскировать. Самая дешёвая идея: CPU-скрипт + 1 арм.
