# Эксперимент 24 — статические входы (орография + маска суша/море)

Дата: 2026-07-16. Ветка: `fix_inline_v2`.

## Цель

Измерить, улучшают ли статические поля — орография и маска суша/море (land-sea
mask, lsm), поданные на вход бэкбона — прогноз трёх семейств моделей на регионе
USA, и меняется ли при этом выигрыш физического приора A2-exp13.

Гипотезы:

- **H1.** Статика улучшает обе армы (no_physics и A2) по RMSE/ACC на общей эпохе.
- **H2.** Выигрыш A2 поверх статики сжимается: диабатический блок уже получает
  орографию/lsm/|lat| через `_load_static_geo`, и часть его вклада может быть
  чисто географической информацией, а не физикой.

## Матрица

6 ранов, seed 0, регион USA (`cut = [[75, 107], [164, 228]]`, 32×64, v4-датасет):

| семейство | арм no_physics + статика | арм A2-exp13 + статика | база без статики |
| --- | --- | --- | --- |
| PI-IAM4VP | `exp24-iam4vp-nophys-static` | `exp24-iam4vp-a2-static` | abl16_long r0/r3 (500 эпох, t12) |
| PI-PredRNNv2 | `exp24-predrnnv2-nophys-static` | `exp24-predrnnv2-a2-static` | exp20 p0/p3 (40 эпох) |
| PI-SimVPv2 | `exp24-simvpv2-nophys-static` | `exp24-simvpv2-a2-static` | exp21_long s0/s3 (500 эпох, t12) |

Бюджет эпох, батчи, lr, датасет — бит-в-бит от родительского конфига базы;
меняется только добавление static-блока и имя рана. Эффект статики = пара
«новый ран vs существующая база» в одинаковом бюджете; армы сравниваются
только на общей эпохе (урок exp16/exp18), парный бутстрап через существующий
harness (`tools/metrics_ladder.py`).

## Механизм: статика на уровне модели (вариант A)

Рассмотрены и отвергнуты: конкат в датасете (ломает канальные инварианты
memmap/нормализации/физблоков, таргеты делят ридер со входом) и конкат в
train-стратегии (у PredRNNv2 авторегрессивная обратная связь живёт внутри
модели — правки моделей всё равно нужны).

Принято: **opt-in на уровне модели**, выход всех моделей остаётся 69 каналов,
физический residual-путь не трогается.

### Общий загрузчик — `utils/static_input.py`

```python
def load_static_input_fields(
    path: str,
    fields: list[str],          # подмножество {"orography", "lsm"}
    cut: list[int],             # [lat0, lat1, lon0, lon1]
    H: int, W: int,
) -> torch.Tensor:              # (S, H, W), float32
```

- Читает `constants_1.40625deg.nc` (h5netcdf), кропит по `cut`, валидирует
  shape против `(H, W)` (LBYL, `raise ValueError`).
- Нормировка: орография — z-score по кропу (`(x - mean) / (std + 1e-6)`);
  lsm — как есть (уже 0..1).
- `PhysicsResidualMixin._load_static_geo` рефакторится на использование того же
  кода чтения/кропа (DRY), поведение диабатического пути — бит-в-бит прежнее.

### Изменения моделей (opt-in, дефолт = прежнее поведение бит-в-бит)

Новые параметры конструктора у всех трёх семейств:
`static_input_fields: list[str] | None = None`, `static_constants_path:
str | None = None`, `static_cut: list[int] | None = None`. При
`static_input_fields=None` архитектура и инициализация не меняются
(регресс-гард). При включении: буфер `self.static_input` через
`register_buffer` (не параметр, в чекпоинт попадает, градиентов нет), S = число
полей.

- **PI-IAM4VP** ([Models/IAM4VP.py](../../Models/IAM4VP.py)): `enc`, `lp`,
  `lp_phys` строятся как `Encoder(C_data + S, ...)`; в `forward` статика
  конкатенируется к каждому кадру `x` и к каждому `pred` перед кодированием.
  `readout`, mask-токены, physics-residual — без изменений. Буфер не потребляет
  RNG, порядок конструирования physics-блоков (фиксирующий инициализацию
  весов) не меняется.
- **PI-SimVPv2** ([Models/SimVP.py](../../Models/SimVP.py)):
  `Encoder(C + S, ...)`, конкат к кадрам на входе; `Decoder` выходит в `C`.
  Skip-связь encoder→decoder: hid-каналы не зависят от C_in — без изменений.
- **PI-PredRNNv2** ([Models/PredRNN.py](../../Models/PredRNN.py)):
  patch_size = 1 в exp20-конфигах, но патчинг поддерживается честно: буфер
  патчится тем же patch_size, вход первой ячейки `frame_channel + S·patch²`,
  `conv_last` выходит в прежний `frame_channel`. В цикле статика подклеивается
  к кадру ПОСЛЕ scheduled-sampling-смешивания реального и сгенерированного
  кадров (оба 69-канальные, статика одна и та же).

## Тесты (TDD, до реализации)

`tests/test_static_input.py` + расширение модельных тестов:

1. Загрузчик: shape `(S, H, W)`, орография нормирована (mean≈0, std≈1 по
   кропу), lsm в [0,1], `ValueError` при несовпадении кропа и (H, W).
   На синтетическом nc-файле во временной директории.
2. Для каждой модели: forward со статикой → выход прежней формы
   `(B, C=69, H, W)` / `(B, T, 69, H, W)`.
3. Регресс-гард: при `static_input_fields=None` — `state_dict` содержит ровно
   прежний набор ключей/shape (никаких новых буферов/параметров), а выход при
   фиксированном seed детерминированно совпадает между двумя конструированиями;
   бит-в-бит против дерева до правки принимается вручную существующим
   harness-приёмом (как в deep refactor 2026-07).
4. PredRNNv2: канальная арифметика при patch_size 1 и 2.
5. `_load_static_geo` после рефакторинга: прежний выход бит-в-бит
   (тот же синтетический nc).
6. Полный прогон существующего pytest — без регрессий.

## Вне скоупа

- |lat| как входной канал (уже неявно в позиционной структуре, YAGNI).
- Полный 2×2 (переобучение баз без статики) — базы переиспользуются.
- Другие регионы (France/North Pacific) — после результата на USA.
- Seeds > 0 — решение после первых результатов, как в exp16.
