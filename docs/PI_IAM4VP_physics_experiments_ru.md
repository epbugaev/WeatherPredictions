## 0. Диагностика: что делает текущая схема и в чём её ограничения

Текущий конвейер residual-corrector (режим, используемый `pi_iam4vp_residual_usa_v4.yaml`):

1. `prev_state → _physics_prior_from_state` прогоняет `HybridBlock` (примитивные уравнения, явный Эйлер,
   `block_dt`, 3 субшага) в физических единицах с конверсией r↔q и тяжёлой стабилизацией → `y_phys`.
2. `delta_phys = y_phys − prev_state` (физическая тенденция).
3. Корректор видит `[y_nn, prev_state, y_nn−prev_state, delta_phys]`, выдаёт **zero-init** свёрточную
   поправку, применяемую **только к upper-air**, регуляризованную глобальным **L1** (`lambda_l1=1e-4`),
   с клиппингом тенденции на 8.0.
4. Обучение per-step с `.detach()` на авторегрессивном стеке → **градиент не течёт по траектории (rollout)**.

Шесть структурных ограничений, каждое — эксперимент ниже:

| # | Ограничение | Следствие |
|---|---|---|
| L1 | `.detach()` на стеке (iterative_manual L117) | поправка оптимизируется под 1 шаг, слепа к росту ошибки на rollout |
| L2 | Физика входит **только как входные признаки** | нет механизма, заставляющего *сам прогноз* подчиняться физике |
| L3 | Явный Эйлер в `PDE_kernel` | жёсткость/неустойчивость → нужны клиппинг+fallback; тенденции-признаки шумные |
| L4 | Глобальный скалярный L1-гейт | нельзя сказать *где* физике доверяют; не интерпретируемо |
| L5 | Захардкоженная геометрия производных 8×16 | блокирует глобус/другое разрешение; плоские операторы на сфере |
| L6 | `upper_air_only`, фикс. `physics_part_coef`, фикс. `block_dt` | приземная динамика не трогается; нет CFL/dt-адаптивности |

Текущая PDE-matrix калибровка (`slurm-pde-matrix-tend-v4-*`) уже показывает ключевое противоречие:
чистый оператор достигает **vs_pure +96.8%**, но **vs_constant всё ещё отрицательный** — голый физический
оператор *ниже persistence*, и именно поэтому нужен обучаемый корректор и почему улучшение самого
оператора (E3–E5) имеет высокую ценность.

## Трек A — Улучшить СУЩЕСТВУЮЩИЙ residual-подход

### E1 — Усечённый BPTT сквозь авторегрессивный стек
**Идея.** Пустить градиент сквозь последние `k` предсказанных кадров, чтобы корректор оптимизировался под
согласованность многошаговой траектории, а не под один шаг. Физические тенденции накапливаются на
6-шаговом rollout; `.detach()` это скрывает.

**Вставка.** `training_strategies/iterative_manual.py`, `_iterate_timesteps` L113–117:
```python
# сейчас: pred_list.append(prediction.detach())
keep_grad = idx_time >= (self.time_prediction - self.bptt_window)   # новый cfg: bptt_window
pred_list.append(prediction if keep_grad else prediction.detach())
```
Конфиг: `training.extra_kwargs.bptt_window: {0 (текущий), 2, 6}`. Следить за памятью (attention +
HybridBlock остаются в графе).

**Метрики.** Кривая rollout RMSE (шаг 1→6), рост `pi_minus_iam4vp_rms`; ожидается более пологий рост
ошибки при k=2.

---

### E2 — Обучаемый пространственно-адаптивный физический гейт (интерпретируемая смесь)
**Идея.** Заменить «свободную свёрточную поправку + глобальный L1» на явный по-пиксельный гейт
`α(x)∈[0,1]`, смешивающий *физическую тенденцию* с обучаемым остатком:
```
y_hat = y_nn + α ⊙ delta_phys + (1−α) ⊙ correction
```
`α` — небольшая сигмоид-свёрточная голова на тех же признаках. Обученная **карта α — публикуемый
артефакт**: «где физика помогает?» — прямой ответ на тезис проекта в виде картинки.

**Вставка.** `PI_IAM4VP.py` `_apply_physics_residual` (~L745): добавить `self.physics_gate`
(Conv→sigmoid), вычислить `alpha`, смешать. Новый флаг `physics_gate: true`. Логировать mean/std `alpha`
по переменным как диагностику.

**Метрики.** Пространственные/вертикальные карты α; корреляция зон высокого α с бароклинными зонами;
RMSE vs текущий гейт.

---

### E3 — Физика как мягкое ограничение на ПРОГНОЗ (настоящий PINN-loss)  ★ ядро тезиса
**Идея.** Сейчас физика — только *признак*. Добавить aux-loss, штрафующий PDE/conservation-остаток
**собственного выхода** модели `y_hat`, вычисляемый операторами, которые уже есть в коде
(`d_x, d_y, d_z, integral_z, laplacian_tensor` в HybridBlock). Минимальный набор:
- **Неразрывность массы:** `‖∇·v + ∂w/∂z‖` (уже считается как `get_w`).
- **Гидростатический баланс:** `‖∂z/∂p + RT/p‖`.
- **Опц. остаток импульса:** `‖(y_hat_u − prev_u)/Δt − u_t_physics‖`.

**Вставка.** Новый метод `IAM4VP.physics_pde_residual_loss(y_hat, prev_state)`, возвращающий взвешенный
остаток; вызвать в `_iterate_timesteps` рядом с `aux_loss` (L119–124):
```python
pde_loss = self._pde_residual_loss(model, prediction, prev_state)
step_loss = forecast_loss + aux_loss + self.lambda_pde * pde_loss
```
Конфиг: `physics_pde_residual_lambda: {0, 1e-3, 1e-2}`, плюс `pde_residual_terms: [continuity, hydrostatic]`.

**Метрики.** Дрейф законов сохранения на rollout (см. E15); снижает ли PINN-член размытие/паразитную
дивергенцию без ухудшения RMSE? Это самая чистая история «физика внутри модели».

### E4 — Интегрирование по времени высшего порядка / полу-неявное в `PDE_kernel`
**Идея.** Явный Эйлер (`var + var_t·dt`) — причина, по которой коду нужны клиппинг, fallback и BN-eval.
Заменить на **RK2 (Heun)** для адвекции и **полу-неявную** обработку быстрых гравитационно-волновых членов
(градиент давления ↔ дивергенция) — это жёсткая часть. Чище тенденции → лучше признаки (E2) и лучше
таргеты для PINN (E3).

**Вставка.** `PredFormerGFT_HybridBlock.py` методы эволюции в `PDE_kernel` (`uv_evolution` ~L328,
`t_evolution` ~L344, `z_evolution` ~L359). Добавить `integrator: {euler, rk2, semi_implicit}` в `HybridBlock`.

**Метрики.** `physics_residual_nonfinite_ratio`, `tendency_clip_ratio` (должны упасть ~до 0); устойчивость
при большем `block_dt`; vs_constant на eval чистого оператора (должно наконец превысить persistence).

### E5 — CFL-осознанный / обучаемый эффективный `dt` и субшаги  (связано с PDE-matrix работой)
**Идея.** `block_dt` и `physics_residual_hybrid_steps` фиксированы. Сделать эффективный горизонт
интегрирования либо **CFL-адаптивным** (число субшагов из `max|v|·dt/dx`), либо **обучаемым скаляром
по уровням** (PDE-matrix прогоны уже подбирают per-level операторы — переиспользовать эту машинерию).
Также условить `dt` на time-embedding IAM4VP, чтобы поздние шаги прогноза интегрировали на горизонт,
соответствующий их lead time (E14).

**Вставка.** `PDE_kernel.__init__` (`block_dt`, L263) → обучаемый `nn.Parameter` по уровням; цикл субшагов
в `_physics_prior_from_state` (~L700). Переиспользовать калибровку `checkpoints/pde_matrix_operator/*`
как инициализацию.

**Метрики.** Профиль обученного dt vs CFL-оценка; устойчивость; vs_constant чистого оператора.

### E7 — Спектральный / Фурье-операторный физический путь (в стиле FNO)  ★ чинит L5
**Идея.** Заменить/дополнить конечно-разностный `PDE_kernel` **спектральным оператором**. Долгота уже
периодична (circular conv), так что FFT по x (и Лежандр/So по y) даёт: точные линейные пропагаторы для
гравитационных/россби-волн, инвариантность к разрешению и **устранение захардкоженной геометрии 8×16**.
Нелинейная адвекция остаётся в физическом пространстве (псевдо-спектрально).

**Вставка.** Новый `Models/blocks/spectral_pde.py`; подключить в `_physics_prior_from_state` за флагом
`physics_engine: {hybrid_fd, spectral}`. Сохраняет тот же интерфейс тенденций-признаков, так что E2/E3
переиспользуют его.

**Метрики.** Перенос разрешения (обучить 32×64 → eval на глобусе `predformer_globe_v4`); спектральная
ошибка (E17); wall-clock vs FD.

## Дисциплина интеграции (в стиле вашего существующего кода)

Каждый эксперимент — **флаг конфига**, валидируемый в `IAM4VP.__init__` (репо уже валидирует
`apply_to`, `feature_mode`, `shuffle`, `hybrid_mode`, `input_space`, `humidity_mode` — следовать этому
паттерну), с дефолтами, сохраняющими текущее поведение, и **zero-init** везде, где добавляется новый
модуль, чтобы каждый arm *стартовал идентично B1* и улучшался только если помогает. Новые лоссы
подключаются к единой точке суммирования в `_iterate_timesteps` (L119–124). Новые диагностики расширяют
`_last_residual_diagnostics`. Это сохраняет каждый arm как однострочный diff конфига и честный тест
«помогает ли физика».
