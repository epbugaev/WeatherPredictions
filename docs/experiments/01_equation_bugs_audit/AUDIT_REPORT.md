# Аудит физических уравнений WeatherPredictions — отчёт

**Ветка:** `checker_equations` (отнаследована от `refactoring`)
**Дата:** 2026-07-02
**Метод:** численное сравнение багованных inline-операторов (`Models/WeatherGFT.py`, класс `PDE_kernel`) с корректным референсом (`tools/check_physics_common.py`) на **реальном ERA5-состоянии** из memmap.
**Данные:** `predformer_usa_2000_2004.dat`, снапшот `2003-07-15 12:00`, USA-кроп 32×64, широтная полоса 25.0–55.0° N, 69 каналов в физических единицах.
**Запуск:** cHARISMa, партиция `cpu-e-quick`, env `weatherpred-refactor` (torch 2.3.1), чистый CPU.

---

## Резюме

Все **пять** ранее выявленных багов подтверждены численно на реальных данных. Три из них дают ошибку в **10⁶ раз** — это прямая причина взрыва «чистой физики» на первом же шаге интегрирования (`frac_ic_blown_up 0→1.0 at h=1`, задокументировано в CHANGELOG).

Критично: багованные операторы живут в **inline-коде продакшн-моделей** (`WeatherGFT`, `PredFormerGFT`, `PredFormerGFT_HybridBlock`, PI-IAM4VP через HybridBlock). Корректный `utils/physics.py` импортируется **только** sanity/check-скриптами и ни одной обучаемой моделью. То есть все обученные результаты работали на неправильной физике.

## Разбор по тестам

### Тест 1 — Кориолис
Код: `self.f = 7.29e-5` — это Ω (угловая скорость Земли), а не параметр Кориолиса `f = 2Ω·sinφ`.
- На 45° N корректное `f = 1.031×10⁻⁴`; код даёт 0.707× от него (занижение на 29%).
- В полосе USA-кропа (25–55° N) отношение члена `f·v` = 0.756, rel_L1 = 0.26.
- Совпадение случайно достигается около **30° N** (`2·sin30° = 1`), вне этого кропа.
- В **южном полушарии** был бы неправильный **знак** (код игнорирует `sinφ<0`).
- `_OMEGA_EARTH` в референсе = 7.2921e-5, `_F_MID_LATITUDE = 2Ω·sin45° ≈ 1.03e-4`.

### Тест 2 — Температурная тенденция
Код: `Q = −L·z_z·w; t_t = (Q − z_z·w)/c_p − адвекция` = `−(L+1)/c_p · z_z·w` = `−2487.6·z_z·w`.
Корректно (первый закон термодинамики, адиабата): `dT/dt = R_d·T·ω/(c_p·p)`, где `ω = 100·w` (гПа/с→Па/с).
- Ядро без адвекции: 5493 K/с (баг) vs 0.0031 K/с (коррект) — отношение 1.8×10⁶.
- max 1.9×10⁵ K/с за один вызов — мгновенный overflow. **Главный источник взрыва при h=1.**

### Тест 3 — Гидростатика и уравнение состояния
Код: `z_zt = −self.R/pressure · t_t`, `p = ρ·self.R·t`, где `self.R = 8.314` (Дж/моль/К).
Должно быть `R_d = 287` Дж/кг/К (газовая постоянная **сухого воздуха**). `R_d` определена в том же файле (`self.R_d = 287`), но не используется в этих формулах.
- Фактор ошибки R: 287/8.314 = 34.5×.
- `z_zt`: суммарно 3.1×10⁶ (усилено багом t_t из Теста 2).
- Уравнение состояния занижает давление в 34.5× (отношение 0.029).

### Тест 4 — Магнус и avoid_inf
Код `q_s`:
```
e_s = 6.112·exp(scale_tensor(17.67·t_c/avoid_inf(t_c+243.5), −3.47, 3.01))·100
q_s = 0.622·e_s / avoid_inf(p − 0.378·e_s)
```
Два дефекта:
1. `p` в знаменателе — в **гПа** (`self.pressure`), а `e_s` в Па → размерное рассогласование, q_s завышен в **1391×** (7.30 vs 0.0052 кг/кг — физически q_s ≪ 1).
2. `scale_tensor` — **batch min-max** нормировка внутри exp → насыщение становится зависящим от батча, а не от физики; жёсткий клип экспоненты в [−3.47, 3.01].

`avoid_inf` unittest — вход `[0.0, 0.05, −0.05, 0.5, −2.0, 3.0]` → выход `[1.0, 1.0, −1.0, 1.0, −2.0, 3.0]`:
- Первый `where` мапит нули в 0.1, но **второй `where` (`|x|<threshold`) перезаписывает** их в 1.0. Нули получают 1.0 вместо задуманного 0.1.

## Методологический вывод

Задокументированный в CHANGELOG результат «чистая физика взрывается → нужна NN-коррекция» **частично является следствием багов 1–3**, а не фундаментальным свойством. Ни одна из ablation (SSP-RK3, гипердиффузия, полярный фильтр, консервативная адвекция, mass-consistent w, semi-implicit) не могла помочь, потому что тенденции завышены в 10⁶ раз ещё до интегратора. `fixC` (scale_diff + `.detach()`) даёт численно конечный, но физически расходящийся результат, потому что `scale_diff` жёстко ужимает любую тенденцию в диапазон ±`diff_ratio·(x−mean)` — маскирует взрыв, не устраняя причину.

**Корректный `utils/physics.py` (`PurePDEKernel`) уже содержит правильные формулы** — его нужно подключить к продакшн-моделям вместо inline-операторов.
