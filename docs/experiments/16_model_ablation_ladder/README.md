# Эксперимент 16 — модельная абляция «лестница уравнений»

Дизайн утверждён 2026-07-09. Статус: подготовка (волна 1 — без порта; волна 1b —
порт exp14/15; волна 2 — сиды 1–2 + якорь).

## 1. Вопрос исследования

Как каждый этап эволюции физического ядра влияет на качество **обученной**
модели при идентичном протоколе (данные, эпохи, LR, сид, архитектура)?
Вклад exp 13/14/15 до сих пор измерен только диагностикой невязок
(docs/experiments/13–15); модельного сравнения через границу фиксов нет —
старые метрики несравнимы (армы обучались на до-фиксовых фичах).

## 2. Лестница армов

Все ступени, кроме якоря, — residual-архитектура PI-IAM4VP (USA v4);
между ступенями меняется **только физический модуль**.

| # | Арм | Уравнения / отличие от предыдущей ступени | Код и конфиг |
|---|-----|------------------------------------------|--------------|
| R0 | `no_physics` | физики нет (контроль архитектуры) | текущее дерево, `pi_iam4vp_residual_no_physics_usa_v4.yaml` |
| R1 | `legacy_hybrid` | оригинальные уравнения статьи, режим `legacy_normalized` (BN-нормализованное пространство) | текущее дерево, `pi_iam4vp_residual_legacy_hybrid_usa_v4.yaml` |
| R2a | `A1-pre13` | v2 pure-physics passthrough, исправленные уравнения эпохи exp 01–12 **до** знаковых фиксов; без диабатика | worktree @ `051e350^` (=a827d32), конфиг massconsistent |
| R2 | `A2-pre13` | + обучаемый диабатический член | worktree @ `051e350^`, конфиг diabatic |
| R3 | `A2+13` | + знаковые фиксы B1–B4 (аудит 13) | текущее дерево, конфиг diabatic |
| R4 | `A2+13+14` | + порт exp 14: адвективная форма, метрика сферы, трение Хелда–Суареса, lagrange3, mass-consistent ω | текущее дерево + новые opt-in флаги hybrid |

## 3. Протокол «одинаковых эпох»

- Данные: train 2000–2003, val 2004; USA-кроп 32×64; memmap
  `predformer_usa_2000_2004.dat` (репак job 4170311); stride 12, batch 16,
  2×GPU DDP.
- Бюджет: **30 эпох**, `training.seed: 0` (обязателен: без него инициализация
  недетерминирована), `val_every_n_epochs: 3` → точки сравнения 3,6,…,30;
  чекпоинт на каждом val.
- Метрики: per-variable RMSE/ACC на val-2004 по эпохам; физдиагностика
  hybrid (tendency_rms, clip_ratio, nonfinite); wall-clock. Comet: один
  проект, имена ранов `abl16-<арм>-s<seed>`.
- Волна 2: сиды 1–2 на всей лестнице (шум-бары); остановка — если эффекты
  ступеней ≫ межсидового шума.

## 4. Порт exp 14/15 в hybrid-ядро (перед R4/R5)

Opt-in параметры `PDE_kernel`/`_evolve_fields` (зеркало `PurePDEKernel`,
дефолты бит-в-бит):

- exp 14: `advective_form`, `metric_terms`, `rayleigh_friction`,
  `vertical_scheme='lagrange3'`, `mass_consistent_w`;
- exp 15: `omega_free=(...)` — ω-члены исключаются из тенденций t,q,u,v,
  но z всегда интегрирует **полный** t_t (два t_t внутри ядра);
  `latent_heating_coupling`; `climatological_sources` — Q₁/Q₂ из
  `docs/experiments/15_deep_equation_improvement/results/eq15_clim_summary_usa_2000.npz`,
  средний пулинг 32×64 → 8×16 (латент-сетка), `register_buffer`.
- Тесты: голден-пин «все флаги выкл = бит-в-бит текущий v2»; знаковые пины
  новых термов (расширение `tests/test_physics_sign_conventions.py`);
  9-арм bit-exact harness.
- Климатологии построены на 2000 годе (внутри train-периода); val-2004
  полностью out-of-sample.

## 5. Порядок исполнения

5. Волна 2: сиды 1–2 + якорь A.

## 6. Ограничения и конфаунды (фиксируются в отчёте)

- R1→R2a — составной шаг: меняются и режим интеграции
  (legacy_normalized→v2 passthrough), и волна исправлений exp 01–12.
  Исторически неразложим (fixedeq-уравнений в legacy-режиме не существовало).
- Геометрия d_y/Δλ в hybrid уже корректна, поэтому модельная ступень
  «+exp14» содержит только термы/форму — в отличие от диагностической exp 14,
  где главный вклад дали геометрические фиксы G1–G3.
- Сравнение R2a/R2 (старое дерево) с R3+ (новое) корректно по task-метрикам:
  loss/metrics/данные идентичны; различие только в физическом модуле.
- Латент-сетка 8×16 — иной баланс шум/сигнал, чем 32×64 у диагностики:
  переносимость эффектов exp 14/15 в модельный путь — открытый вопрос,
  который этот эксперимент и измеряет.

## 8. Результаты (обновляется по мере готовности армов)

**Статус на 2026-07-10:** готов R0 (baseline); R1, R2a, R2, R3, R4, R5 в очереди
(кластер GPU-насыщен, fairshare просел — не блокер кода, вопрос времени).

### 8.1. Отклонения от протокола (§3) при исполнении

- **1×GPU** вместо 2×GPU DDP: 2-GPU-джобы оценивались на +2 суток очереди;
  на 1×GPU полный ран R0 = **27 мин** (a100), backfill-дружелюбнее. Метрики
  сравнимы (тот же loss/данные/эпохи); межарменное сравнение не затронуто.
- Окружение `pi-iamvp` (клон predformer + timm 1.0.11 + h5netcdf + matplotlib);
  запуск из git-worktree требует копии `.env` с Comet-ключом (worktree не
  наследует gitignored `.env`).
- Метрики Comet — **по-уровневые** (RMSE_z500_mean, RMSE_t850_mean, …,
  поверхностные t2/tp/u10/v10), а не 5 переменных: `make_figures.py`
  сворачивает уровни в базовые переменные (z/t/r/u/v; r = относительная
  влажность) усреднением по уровням поэпохно.

### 8.3. Как читать вклад ступеней (по готовности R1–R5)

Вклад ступени = знак и величина разности её кривой и предыдущей на **тех же
эпохах**. Ключевые дельты: R0→R1 (интеграция оригинальных уравнений),
R2→R3 (знаковые фиксы аудита 13), R3→R4 (термы/форма exp 14), R4→R5
(ω-free + скрытое тепло + клим. Q₁/Q₂ exp 15). Отрицательная дельта (RMSE
растёт) = ступень в модельном пути вносит шум, а не сигнал — прямая проверка
переносимости диагностических выводов exp 13/14/15 на латент-сетку 8×16 (§6).
